## Required fix (design is decided; implement it)

Workers are spawned with `start_new_session=True`, so the worker pid IS the
session id of every descendant, transitively, and no unrelated process can be
in that session. The SESSION is the correct ownership invariant, not the group.

In `_signal_worker_tree(pid, sig, ...)`:

1. Keep the existing group signal when `getpgid(pid) == pid` (cheap, covers
   the common case) AND keep the single-pid fallback.
2. ADD: derive the owned set by enumerating live processes and selecting every
   pid whose `os.getsid(candidate) == sid` where `sid = os.getsid(pid)`, and
   ONLY when `sid == pid` (proof we created that session; if the worker is not
   its own session leader we do NOT own the session and must not scan it).
   Signal each such pid individually. This is DERIVED from the OS, never from a
   hand-maintained list — that is a hard requirement (see AGENTS.md guard rules).
3. Also signal any separate process GROUPS discovered inside the owned session
   (group leaders found in the scan) so a group with a child that outlives the
   enumeration is still covered.
4. PID-reuse safety: before signalling a scanned pid, re-verify its session id
   immediately before the kill; skip on any exception.
5. Everything must stay injectable for tests: keep `kill`, `killpg`, `getpgid`
   params and add `getsid` and a `scan_pids` (iterable-of-pids) injectable.
   When `signal_fn` is injected by a caller it must intercept every signal path
   (as it already does for kill/killpg) — no path may reach a real `os.kill`.
6. psutil is a declared dependency (pyproject.toml line ~113). Prefer psutil for
   enumeration, but degrade gracefully (no hard import failure) if absent.
7. Windows: `getsid`/`killpg` absent — must fall back to the plain pid signal
   without raising.

Apply it to BOTH termination paths that already call `_signal_worker_tree`:
`_terminate_reclaimed_worker` and `enforce_max_runtime`.
